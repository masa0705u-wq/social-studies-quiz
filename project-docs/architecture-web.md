## 論理データの対応

従来18シートの意味を維持し、物理的なSheets2ファイル指定を置換する。

- Questions/Answers/QuestionImages/Sources/QuestionSources/Categories: catalog.questionsと埋込の別解/画像/出典。分野・難易度は検証済み列挙値。
- SchoolYears/Classes/Groups/Settings: catalog文書。過年度は削除せず追記。
- Games/GameQuestions/Participants/Scores/GameResults: game:UUID文書。出題時の問題内容・画像参照を固定。
- Responses/AuditLogs: quiz_events表とゲーム内の監査。回答は最後の受理回答とヒント前正答の要約をゲームに持ち、全送信履歴はイベント表へ保存。
- BackupRuns: backup:UUID文書。復元はrestore:UUID名前空間と独立ファイル領域で検証。

ID/日時/不変スナップショット/正規化/正答率の定義は元仕様を維持。JSON文書は1.5MBまでとし、超過は明示エラーにする。回答本文の全履歴をゲームJSONへ蓄積しない。

## 同時処理と画像参照

CAS失敗時は現状態を読み直す。requestIdのイベントを確認し再送は元の受理結果を返す。状態更新のmutation IDと一致したときだけ、同一トランザクション内で履歴を追加する。古いCASで監査だけ残さない。

画像を使うゲームは、問題版を再確認し、参照ファイルをcatalogの保護集合へ予約してから作成。物理削除は同じcatalogのCASで参照確認・削除予約を行う。画像添付は予約済みファイルを拒否。過去ゲームで参照したファイルは保護を継続する。

## 自動バックアップ

手動/定期用の共通処理は設定周期・排他リース・保存世代を確認する。Workerのscheduledハンドラと毎時の設定を実装。Sitesの公開基盤での定期起動は、別途実際の設定・実行を検証する。加えて、所有者認証済みMCPのbackup_if_dueを提供し、Sitesのクラウドスケジュールから安全に呼べる構成を用意する。定期実行の成立を未検証のまま完成としない。
